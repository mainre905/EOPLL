## 0. 지금 어디까지 되고 어디서 멈추는가

| 단계 | 상태 |
|---|---|
| 프로젝트 생성 (소스 + XDC + BD + IP) | 이 가이드로 한다 |
| 합성 (synth_1) | 이 가이드로 한다 |
| 구조 확인 (`check_build.tcl`, S1~S6) | 이 가이드로 한다 |
| 구현 · 비트스트림 | **안 한다. 스크립트가 여기서 멈춘다** |
| 보드 테스트 | 못 한다 (비트스트림이 없으므로) |

**왜 멈추나** — 합친 보드의 FMC 핀맵이 아직 정해지지 않아 DAC 핀
(`dac_sck` / `dac_cs_n` / `dac_sdio0..3` / `dac_ctrl_tri_io`)에 LOC 가 없습니다.
핀이 안 박힌 I/O 로 비트스트림을 뽑으면 Vivado 가 남는 핀에 임의로 배치하고,
그 비트스트림을 합친 보드에 올리면 **어떤 핀이 구동될지 모릅니다.**
그래서 통과시키지 않고 `build_eopll.tcl` 이 합성 직후에 멈추도록 해 뒀습니다.

즉 이번 빌드의 목적은 **"합쳐진 설계가 합성되고, TDC 지연선 구조가 그대로인가"** 하나입니다.

## 1. 먼저 — 보드를 건드리기 전에 J18 확인

이번 절차는 비트스트림을 만들지 않으므로 **보드를 연결할 필요가 없습니다.**
그래도 노트북에 보드가 물려 있다면 J18(VADJ) 위치를 눈으로 확인해 두십시오.

| 프로젝트 | J18 | 이유 |
|---|---|---|
| TDC | **2.5 V** | 히트 입력이 FMC LA27 의 `LVDS_25` + `DIFF_TERM` |
| DAC | **1.8 V** | AD3552R 디지털 입력 절대 최대값이 `min(VLOGIC+0.3, 2.1) V` — 2.5 V 는 **절대 최대 초과** |

합친 보드에서는 점퍼를 프로젝트마다 옮길 수 없으므로 VADJ 를 하나로 정해야 합니다.
`../DAC/Markdown/2026-09-09_J18_통합_전압설계.md` 의 **권고는 B안**(전부 2.5 V + DAC 디지털선에
레벨 시프터)입니다. TDC 히트 경로가 이미 `LVDS_25` + `DIFF_TERM` 으로 특성이 측정된 쪽이라,
수신 규격을 바꾸면 LSB 15.625 ps 와 진입 트랜지언트 측정값이 전부 무효가 되기 때문입니다.
**핀맵을 정할 때 이 문서를 먼저 읽으십시오.**

## 3. Vivado GUI 에서 프로젝트 생성 + 합성

Vivado 2024.1 을 띄우고 (프로젝트는 열지 않아도 됩니다) **Tcl Console** 에 아래를 붙여 넣습니다.
`-mode batch` 는 쓰지 않습니다. 경로 구분자는 반드시 `/` 입니다 — Tcl 에서 `\` 는 이스케이프입니다.

```tcl
cd D:/Study/Programming/FPGA/Source/EOPLL
set argv {2 eopll_m2 1} ; source build_eopll.tcl
```

★ 경로의 `\` 를 `/` 로 바꿔 쓴 것입니다. 탐색기가 보여 주는
`D:\Study\Programming\FPGA\Source\EOPLL` 를 그대로 붙여 넣으면 Tcl 이 `\S`, `\P`, `\F` 를
이스케이프로 먹어 **에러 없이 엉뚱한 경로**가 됩니다.

인자 세 개의 뜻:

| 인자 | 값 | 뜻 |
|---|---|---|
| 1 | `2` | `OPERATION_MODE` = 2 (외부 히트 = FMC LVDS 비교기). 0=위상스윕 / 1=링오실레이터 |
| 2 | `eopll_m2` | 프로젝트 폴더 이름 → `vivado/eopll_m2` |
| 3 | `1` | 합성과 구조 확인까지 이어서 실행 (핀맵 전까지는 여기서 멈춘다) |

프로젝트만 만들고 합성은 GUI 버튼으로 하고 싶으면 세 번째를 `0` 으로 주십시오.
구현 전략(`Performance_ExplorePostRoutePhysOpt`)은 어느 쪽이든 미리 걸립니다.

### 스크립트가 중간에 스스로 멈추는 지점들 (전부 의도된 것)

| 메시지 | 뜻 | 할 일 |
|---|---|---|
| `이미 있다: .../vivado/eopll_m2` | 같은 이름의 프로젝트가 이미 있다 | 폴더를 지우거나 두 번째 인자를 다른 이름으로 |
| `VCO 가 ... MHz 다. 1000 MHz 여야 한다` | `clk_wiz_0` 설정이 틀렸다 | 멈춘 이유가 맞다. 위상 스텝 17.857 ps 가 깨진다 |
| `clk_out2 에 fine phase shift 가 안 켜졌다` | MMCM fine PS 미설정 | 이게 안 켜지면 위상 이동이 **아무 효과가 없는데 성공한 것처럼 보인다** |
| `구조 확인 실패 N 건 (지연선 단수 또는 탭 수)` | 캐리체인이 96단/384탭이 아니다 | 비트스트림이 의미 없으므로 진행하지 않는다 |

| 경고 | 어디서 | 무엇인가 | 조치 |
|---|---|---|---|

DAC 저장소도 같은 지점을 기록해 뒀다 (`../DAC/Markdown/2026-09-09_chirp_ddr_dma.md` §10.3, 그리고 §10.6 의 "LUT 에 IOB 를 걸어 봐야 의미가 없다") | 핀맵 전에는 판단 불가. 아래 참조 |

### 9-1. `RTL/dac_timing.tcl` 이 빠져 있었다 (2026-09-21 수정)

첫 빌드에는 이 파일이 제약 파일셋에 안 들어가 있었다. 이 파일이 하는 일은 셋이다:

1. SPI 출력 타이밍 제약 (`set_output_delay`, AD3552R Table 4 의 t7/t8 = 2 ns 에 배선 1 ns 를 더해 3 ns)
2. `axi_quad_spi` 안의 **낡은 `IOB=TRUE` 를 푼다** — 위 `Place 30-73` 의 `spi_0` 쪽 원인
3. FSM 출력 레지스터에 **IOB 패킹을 요청한다** — 이게 빠지면 플롭→패드 배선이 길어진다.
   DAC 저장소에서 이것 때문에 **WNS −4.992 ns** 가 났고, 고친 뒤 +0.751 ns / IOB 6/6 이 됐다
   (`../DAC/Markdown/2026-09-09_chirp_ddr_dma.md` §10.4~10.6, `2026-09-12_report.md`).

XDC 가 아니라 `.tcl` 인 이유 : XDC 의 제한된 인터프리터는 `if`/`foreach` 를 지원하지 않는다.
DAC 저장소에서 2026-09-09 에 `if` 블록이 통째로 건너뛰어져 **SPI 출력 제약이 하나도 안 걸린 채**
비트스트림이 나왔고, 검사할 제약이 없으니 타이밍 리포트는 깨끗해 보였다. 조용히 틀리는 종류다.

`build_eopll.tcl` 이 이제 `PROCESSING_ORDER LATE` 로 넣는다. 합성 로그에서 **`!!!!`** 를 검색하면
이 스크립트가 실패한 항목을 볼 수 있다.

### 9-2. DAC 출력 타이밍은 핀맵 전까지 판정할 수 없다

`set_output_delay` 는 핀이 박혀야 의미가 생기고, IOB 패킹도 대상 IOB 가 정해져야 한다.
그러니 `Place 30-73` 이 문제인지 아닌지는 **핀맵이 들어간 빌드에서** 판정한다.
그때 볼 것은 DAC 저장소가 쓰던 기준 그대로다 — 출력 레지스터가 IOB 에 실렸는지(6/6),
그리고 `dac_sck_gen` 기준 WNS 가 양수인지.
