## 1. 무엇을 확인하려 했나

TDC 와 DAC 를 한 PS7·한 인터커넥트 아래로 합친 뒤(커밋 `c3140d7`), **TDC 가 예전처럼 도는지**를
보드에서 처음 확인했다. 비교기는 쓰지 않았다 — Mode 1(링오실레이터)과 키 4(DPS 위상 스윕)는
전부 칩 내부 신호라 FMC 도, J18(VADJ)도 필요 없다. 키 2(외부 LVDS)는 누르지 않았다.

합친 보드의 FMC 핀맵이 아직 없어 비트스트림을 못 만드는 문제는 **시험 전용 임시 핀맵**
(`RTL/eopll_testpins.xdc`)으로 풀었다. DAC 핀을 PMOD JB/JC 로 보낸다 — 뱅크 13, VCCO 3.3 V
고정이라 J18 과 무관하고 FMC 로는 아무 신호도 안 나간다.

앱은 TDC 것을 **한 줄도 안 고치고** 썼다 (`vitis/tdc_app.c`, `../TDC` 커밋 `f935720`).
통합하면서 옮긴 주소는 DAC 쪽(`0x43C0_0000` → `0x43C1_0000`)이고 `TDC_BASE` 는 그대로다.

끝 칸을 0/2/5/10칸 잘라도 최대값이 안 변한다 (탭 276 은 창 안쪽). 끝 칸이 만든 값이 아니다.

### 3-2. 검증 — 보드 계산 ↔ Orin 재계산

원자료의 val 히스토그램 384칸에서 Orin 이 같은 식으로 다시 계산했다.

| 항목 | 보드 | Orin 재계산 |
|---|---|---|
| DNL 전 min / max / rms | −0.982 / +2.931 / 0.697 | −0.982 / +2.931 / 0.697 |
| INL 전 최대 (탭) | 67.47 ps (113) | 67.47 ps (113) |
| INL 전 p-p / 가중 rms | 91.10 / 29.41 ps | 91.10 / 29.41 ps |
| INL 후 최대 (탭) | 3.20 ps (276) | 3.20 ps (276) |
| INL 후 가중 rms | 1.29 ps | 1.29 ps |

쓴 식은 보드와 같다 — 칸 폭 `w[i] = h[i]/H × 5000 ps`, 참값 `(앞칸합 + h[i]/2)/H × 5000`,
교정 전 표 `floor(((2(i−lo)+1)×5000 + N) / (2N))`, DNL `w/LSB − 1`, INL `표 − 참값`.
**INL 후는 교정표가 로그에 남은 탭 159~321 구간만 계산했다** (§7) — 최대값(탭 276)이 그 안이라
보드 값을 그대로 재현했다.

## 5. 지연선은 같은 물건인가

단독과 통합의 **val 히스토그램**(둘 다 200만발, 같은 링오실레이터 자극)을 공통 구간
탭 2~319 에서 비교했다.

| 항목 | 값 |
|---|---|
| 칸 폭 패턴 상관계수 | **r = 0.9827** |
| 칸 폭 차이 | rms 2.10 ps, 최대 21.03 ps (탭 300) |
| 제일 넓은 칸 | 단독 82.6 ps (탭 300) → 통합 **61.6 ps** (탭 300) |
| 히트가 찍힌 칸 | 단독 2~319 → 통합 **2~321** |
| 탭 320 / 321 히트 | 단독 0 / 0 → 통합 2,729 / 2,619 |

패턴이 그대로다 — 같은 물리적 캐리 체인이다. 달라진 것은 창이 2칸 늘어난 것과 탭 300 이
좁아진 것인데, 이는 TDC 저장소가 기록해 온 **"빌드마다 창이 옮겨간다"** 그대로다.

★ **온도로는 설명되지 않는다.** 통합 쪽이 2 °C 더 뜨거운데(47.5 대 45.5), 더우면 칸이 넓어져
창이 **줄어야** 한다. 실제로는 늘었다. 배치 차이로 보이지만 **확인된 바 없으므로 가설이다.**

## 6. 타이밍 — 구조는 그대로, 위반은 DAC 출력에만

`vivado/eopll_tp2/build_check.txt` : 구조·배치 항목 **전부 PASS**, FAIL 은 T1 하나.

| 항목 | 결과 |
|---|---|
| S1 캐리체인 단수 / S2 탭 수 | 96 / 384 |
| P1.0~P1.3 탭0 FF 배치 | **SLICE_X42Y0** AFF/BFF/CFF/DFF, CO→D SLOW_MAX 91 ps (#3 만 336) |
| P2 히트 먹스 배치 | **SLICE_X41Y0** A6LUT |
| R1 링오실레이터 | 31/31 pblock 안 |
| T2 hold WHS | **+0.033 ns** |
| **T1 setup WNS** | **−3.587 ns → FAIL** |

위반 경로 5개가 **전부 DAC 출력**이었다 (`clk_fpga_0` → `dac_sck_gen`, 출력 플롭 → PMOD 패드).
도메인별로 나눠 보면 TDC 는 전부 양수다:

| 클럭 | WNS | 비고 |
|---|---|---|
| `clk_out1_clk_wiz_0` (샘플링 200 MHz) | **+0.034 ns** | 단독 09-16 은 +0.165 ns |
| `clk_out2_clk_wiz_0` (히트 생성 200 MHz) | +0.854 ns | |
| `clk_fpga_0` (AXI 100 MHz) | +1.006 ns | |
| `RO_CLK` | +2.706 ns | |

**왜 DAC 만 위반했나** — `RTL/dac_timing.tcl` 의 출력 제약은 DAC 단독 프로젝트의
**FMC 핀 + IOB 패킹** 전제로 맞춘 것이다. 시험 핀맵은 (1) 핀이 PMOD 로 전혀 다르고,
(2) `sdio1` 삼상 레지스터가 IOB 에 안 실리며(`Place 30-73`), (3) `eopll_testpins.xdc` 가
`SLEW SLOW` 를 걸어 출력 버퍼가 느리다. 생성 클럭 `dac_sck_gen` 이 그 버퍼 뒤 **패드에서**
정의되므로 예산이 더 깎인다.

**측정에는 영향이 없다.** DAC 는 `CTRL.EN=0` 으로 정지 상태였고 출력이 가는 곳은 빈 PMOD
헤더다. 그래도 위반이 WNS 를 가려 판단을 흐리므로, 커밋 `e9154ba` 부터 **시험 핀맵일 때는
`dac_timing.tcl` 을 넣지 않는다.** 실제 핀맵이 들어오면 반드시 다시 넣고 평가할 것.

★ **샘플링 도메인 여유가 +0.165 → +0.034 ns 로 줄었다.** 통과는 통과지만 34 ps 는 얇다.
EOPLL 루프 RTL 까지 들어오면 여기가 먼저 바닥난다. 그때는 popcount 트리에 파이프라인 단을
하나 더 넣는 것이 정석이다.

## 7. 기록에 없는 것 — 로그 앞부분이 잘렸다

`tdc_dac_merge.csv` 는 교정표 CSV 중간(탭 159)에서 시작한다. 터미널 스크롤백이 모자랐다.
그래서 다음이 **확인되지 않았다** :

- `i` 출력 전체 (ID `0x54444302`, MMCM locked, DNA)
- 키 1 의 **HIT_CNT ↔ 384칸 합 일치 여부**, DROP_CNT, 링오실레이터 주파수,
  **DANGER lo/hi**, 교정 RAM 512칸 되읽기 결과, 창 보고

키 4 끝에 `DROP_CNT = 0` 이 찍혔으므로 히트 손실은 없었다고 볼 수 있으나, 키 1 시점의
값은 아니다. **다음에 `i` → `1` 만 다시 찍어 기록을 채울 것.**

## 8. 다음 할 일

1. **`i` → `1` 재캡처** — §7 의 빈칸을 채운다. 스크롤백을 넉넉히 잡을 것.

   (단독 데이터에서 cal↔val 한 쌍으로 잰 값이 1.56 ps 였고, 이는 산탄잡음 기대치 2.40 ps 의

4. **실제 보드 핀맵** — 정해지면 `eopll_testpins.xdc` 를 빼고 새 XDC 를 쓰고,
   `dac_timing.tcl` 을 다시 넣어 DAC 출력 타이밍을 **처음으로 제대로** 평가한다.
5. **EOPLL 루프 구조 결정** — 주파수 락(PLL)이냐 주기별 predistortion(repetitive control)이냐.
   이것이 정해져야 루프 RTL 을 짤 수 있다.
